Ledger, round 2: the rules

Thesis. A rich-text band is a ledger. The eyebrow and h2 sit above the body at the one left edge, and the body's own structure (h3 groups, lists, statements, name and description pairs, long prose) is laid across all twelve columns as ruled rows and ruled columns. Paper and ink, hairlines only, no boxes, no fills. Reference: Trinity Church Wall Street (research note section 3, item 2). Borrowed this round: the said-list setting from B, and balanced prose columns for long continuation prose from C.

Final classifier

// Input: the band's Portable Text blocks + whether it has a heading/eyebrow.
// text(b)  = splitStega(spansText(b)).cleaned      // never measure a stega string
// words(s) = text.trim().split(/\s+/).length
// segs     = consecutive listItem blocks grouped into one list; h3, h4, normal kept

shape(band):
  hasHead = heading || eyebrow
  if hasHead && H3 == 0 && H4 == 0 && lists == 0
            && paras <= 3 && total <= 80                    -> ROW
  if H3 >= 2 && every h3 group is paragraphs only
            && every group <= 150 words                     -> COLUMNS(n = H3)
  if H3 >= 1 || H4 >= 2                                     -> SECTIONS
  if paras >= 8 && share(paras <= 35 words) >= 0.8          -> REGISTER
  if some list has >= 3 items && listWords/total >= 0.4     -> LEDGER
  else                                                      -> PROSE
  !hasHead  -> the same shape, drawn as a CONTINUATION: no head, no lede,
               top padding at section-md                    (ROW cannot occur)

ROW:        head cols 1-5, text cols 6-11, top-aligned; each paragraph is a ruled sub-row
COLUMNS(n): across = n <= 4 ? n : (n % 3 == 0 ? 3 : 4)   // 4 across for four
            2x2 below 1200px, 1 across below 700px
            a group of <= 40 words sets its text at the item size

flow(segs)   // the one renderer every branch uses for its runs
  PARAGRAPH RUN (consecutive normal blocks), T = its words:
    LEDE      headed band, first run, first para <= 40 words
              and (run == 1 || run >= 3 || it ends with ":")
    STANDFIRST band-level, all or none: every h3 group that opens with 2+ paragraphs
              opens with one of <= 30 words -> those first paragraphs italic, item size
    LEAD-IN   last para of a run ends with ":", <= 25 words, a list follows
                                                                -> italic, item size
    MEASURE   T <= 60, or one paragraph of <= 110 words        -> cols 1-7, 62ch
    RUN2      otherwise, ceil(T / 150) <= 2                     -> 2 columns, cols 1-10, 17px
    RUN3      ceil(T / 150) >= 3                                -> 3 columns, full width, 16px
              split into sets of about 600 words, a hairline between sets
  LIST L (item text cleaned):
    TABLE     >= half the items contain " | "          -> name cols 1-4 | text cols 6-11
    SAID      no " | ", shared first 1 to 3 words across every item,
              shorter than the shortest item, and (items >= 3 || prefix >= 2 words)
                all items <= 6 words -> inline TRIAD with the prefix in gold-ink
                else                 -> SAID rows: italic, item size, prefix in gold-ink;
                                        prefix <= 6 chars is HUNG into the gutter at >= 1024px
                                        (text keeps the band's left edge), else its own track
    TRIAD     every item <= 6 words, <= 4 items         -> one line, hairline separators
    INDEX     every item <= 6 words, >= 5 items         -> ruled rows in 3 columns
    PLAIN     otherwise                                 -> ruled rows, item size
  H4 RUN     2+ h4 groups -> COLUMNS (3 across max); FLUSH (no column rules)
             when it opens its h3 section, because the section rule is already there
  RUN-IN     paragraph /^(Label) [-–] (text)$/ where Label is 1-4 words, <= 28 chars,
             no ".", every word capitalised (of/and/the/to/in/for allowed), AND at least
             two paragraphs in the same band match      -> label in the UI face, sub-row
  FOOT       last block is a para <= 15 words and either follows an h3/h4 group
             or is a link line                          -> closing ruled row, muted

Every band, and the branch it hits

Per branch: what renders, and why

  • Every headed band: eyebrow and h2 above, at the one left edge; the body gets all twelve columns. Two internal edges repeat: col 1 and col 6 (the column ImageText already starts its prose on), so halves, table text and row text line up down a page.
  • COLUMNS: each h3 group is a column under a strong hairline. Four across only from 1200px; below that, 2x2.
  • SAID (from B, replacing round 1's numbered covenant): a list whose items all open with the same words is a text said aloud. The shared words sit in their own narrow gold-ink track so the verbs align; the rest is italic at the item size; hairlines stay because this is still the ledger. No numbers: the church never numbered it. Hits the covenant ("To"), the confession list ("That"), and the "God is" triad in the creed.
  • REGISTER (kept from A): the creed stays a two-column ruled register, read down then across. B's single-column said setting was considered; the register is denser and the client preferred A. The embedded "God is" list takes the SAID idea in its triad form, prefix in gold-ink.
  • RUN2 / RUN3 (from C): long prose goes into balanced columns instead of one long column. This is what stops History running down one column for thousands of pixels. RUN3 uses the dense 16px size; phones get one 17px column.
  • CONTINUATION: round 1's "Continued" margin label is gone. A headingless band is simply the same system with no head, starting at the left edge, on a tighter top padding. History's six continuations now read as column sets and sections, not a strip on the right.
  • INDEX (new this round): Contact's ten one-line items as ruled rows in three columns, not a ten-row ledger.
  • STANDFIRST (new this round): History's h3 sections open with a one-sentence summary before the story. It is a band-level, all-or-none test (every h3 group opening with two or more paragraphs must open with one of 30 words or fewer), so a band never mixes italic and roman openings; Four commitments fails it on The Way (37 words) and stays roman throughout.
  • ROW: short headed bands (Give, the CCT intro, Affiliation) on one ruled line at desktop, top-aligned, each paragraph its own ruled sub-row (Give's three ways read as three rows); above 60 words the text drops to body size.

New strings

None. Round 1's "Continued" is gone. The page dividers and specimen labels are prototype chrome, not design.

Sizes added

Two, the allowed maximum: --item: clamp(1.125rem, 1rem + .4vw, 1.375rem) for list rows, register statements, said text, table names and row text; --dense: 1rem for three-column prose only. The two-group h3 now reuses the lede token instead of a clamp of its own.

Cadence

No exception. Surfaces here are the ones the live pages assign today. Still true: a continuation would read better on its predecessor's surface; that would be a cadence exception and is not taken.

Honest weaknesses

  • /ministries "Sunday, room by room" and "Adults" are the densest bands on the site: sub-heads, rows, tables and columns in one band. Orderly, but a lot of hairline.
  • RUN2 applied to the pastors' letter (who-we-are, staff) sets a letter as two newspaper columns. It reads, but a letter is the one kind of prose that might deserve a single measure; there is no signal in the body that says "letter".
  • RUN3 at 16px is denser than the rest of the site's reading; it is only used above 300 words and only at desktop.
  • The SAID test cannot tell a spoken text from a list that merely repeats a word ("The Nursery / The Kids Center"). Requiring three items or a two-word prefix makes it rare, not impossible.
  • /beliefs is register, sections, prose, said, columns, prose back to back: the rules dominate that page.
