# The anatomy of "generic AI design" and how to escape it

Research compiled 2026-09-20. Sources are cited inline; URLs are listed once at first citation and can be reused. Where an article was fetched and read in full, that is noted; where a claim comes only from a search snippet, it is marked "(search summary only)."

---

## 1. The tells

A checklist of specific, nameable markers. Each has the one-line reason it reads as generic, and a source where one named it.

### Typography

1. **Inter (or Inter-adjacent geometric sans) set as the only typeface, especially the centered hero headline.** Reads as generic because Inter was built to be neutral UI chrome at small sizes, not a voice, and it is now the default fallback in nearly every AI design tool and component library, so it signals "nobody made a typographic decision here." Named in [Shuffle's "Why Do Most AI-Generated Websites Look the Same"](https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/) and the [Developers Digest "16 patterns" piece](https://www.developersdigest.tech/blog/ai-design-slop-and-how-to-spot-it), which lists "Inter used for everything, especially the centered hero headline" as pattern #1.
2. **The Space Grotesk / Instrument Serif / Geist pairing.** This trio has become the "distinctive-looking" default precisely because so many AI tools reach for it as their one gesture toward personality, which cancels out the personality. Named in Developers Digest as pattern #2.
3. **A serif italic used to highlight one word inside an otherwise all-sans headline** ("Build the future of **work**"), with no typographic or narrative reason the emphasis word earns special treatment. Developers Digest pattern #3; also independently named as "Type Reflexes" ("Italics for emphasis the content never earned") in [solodesign.cc's "AI design slop: the tells"](https://solodesign.cc/blog/ai-design-slop-the-tells/).
4. **Monospace set as body copy**, borrowed from developer-tool aesthetics for a site that has nothing to do with code. Reads as a category error: mono exists to align code characters, not to be read in paragraphs. Named in solodesign.cc.
5. **All-caps section labels and headings used as a default weight**, rather than a deliberate accent. Developers Digest pattern #16; also flagged as part of "permanent dark mode" styling in the same piece.
6. **A whole page in one typeface with no scale contrast** — same weight from hero to footer, no display size doing anything a body size couldn't. This is the mechanical result of using a component library's default type scale untouched (see Section 2).

### Layout

7. **Hero + three feature cards + testimonials + pricing + CTA, in that order, every time.** This is the single most cited generic-AI structure. Named explicitly in [Shuffle](https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/): "the model defaults to the most statistically common layout it has seen: hero section, three feature cards, testimonials, pricing, CTA."
8. **Centered hero, single CTA, badge sitting directly above the H1.** Developers Digest patterns #9 and #10. Reads as generic because centering is the layout that requires zero compositional judgment; a badge-over-headline is copied wholesale from a thousand SaaS templates rather than earned by content.
9. **Identical band padding and identical card heights, page-wide** — the same vertical rhythm and the same box dimensions section after section, regardless of what the section is actually saying. Named directly in the [925 Studios AI slop guide](https://www.925studios.co/blog/ai-slop-web-design-guide) (fetched in full): "identical padding, identical border radius, and identical card heights throughout."
10. **16px (or 20-28px) border radius applied to every rectangle on the page** — cards, buttons, images, inputs — with no variation. 925 Studios names this literally: "16px border radius everywhere." The [bento grid write-up at Superdesign](https://superdesign.dev/styles/bento-grid) independently notes bento's own tell is "a characteristic radius of 20 to 28px plus a single consistent gap," meaning the radius itself, not the grid, is what most strongly signals "template."
11. **Bento grids used as decoration rather than to solve an actual information-density problem.** Search summary (multiple sources) notes that Linear, Vercel, Cursor, Notion, Reflect and Framer are all cited as the source of the bento trend, yet **none of them currently run a bento homepage** — the pattern outlived the sites that made it famous and is now a tell of imitation rather than of the tools it imitates.
12. **Max-width container with everything centered inside it, no element ever touching or crossing the edge of the viewport.** This is the default behavior of any framework grid used without modification, and its absence of edge tension is why it reads as inert. Consistent with the Smashing Magazine point below that a real layout is defined by *where it breaks the rule*, not by how consistently it obeys it.
13. **Icon-card grids: identical cards, each with a small icon centered above a heading and one line of body copy**, repeated three, four, or six times. Developers Digest pattern #12.
14. **A numbered "1, 2, 3" step sequence used as a generic structural crutch** rather than because the content is genuinely sequential. Developers Digest pattern #13.
15. **A full-width stat banner ("10,000+ users / 99.9% uptime / 24/7 support")** dropped in as connective tissue between sections rather than because those numbers are the most important thing on the page. Developers Digest pattern #14.

### Colour

16. **Purple-to-blue (or "VibeCode Purple," a specific lavender) gradients**, especially behind hero text or as a CTA background. This is called out as *the* most recognizable AI tell across nearly every source searched, including [Shuffle](https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/), [Developers Digest](https://www.developersdigest.tech/blog/ai-design-slop-and-how-to-spot-it) (pattern #4), and [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide). The mechanism named by Shuffle is instructive: "if a beautiful site with a purple gradient gets enough attention, it makes it into the training data, and the next week, every AI tool is defaulting to purple gradients" — a feedback loop, not a considered choice.
17. **A colored "glow" or blurred box-shadow behind hero cards and buttons** ("dark-SaaS glow"). Named in solodesign.cc as a mechanically repeated combination ("dark bento + bright accent + glow").
18. **Emerald/safe green as the fallback accent once purple is blocked.** Solodesign.cc calls this out specifically: when a designer or a system prompt forbids purple, the model reaches for green next, revealing that the choice was reactive rather than intentional in the first place — "the next safe distinctive color."
19. **A warm amber/cream accent wash used to signal "tasteful startup," applied regardless of whether the brand is serious, B2B, or otherwise mismatched to that register.** Solodesign.cc names this "the em-dash of design," a direct analogy to how a single overused prose tic gives away machine authorship.
20. **Permanent dark mode with medium-grey body text on black/near-black, all-caps labels layered on top.** Developers Digest pattern #5, frequently paired with poor WCAG AA contrast (pattern #6).
21. **Glassmorphism (translucent, blurred panels) applied everywhere rather than to one or two functional surfaces**, which both undercuts contrast/accessibility and costs real render performance. A 2026 trend retrospective found "teams that went heavy on the effect seeing 15 to 30 percent FPS drops on real user devices" and concluded glass now reads as "a design tool rather than a trend," legitimate only when restrained to nav bars, modals, or single feature cards (search summary, multiple 2026 sources).

### Imagery

22. **Stock photography of a "diverse group of people looking at a laptop in an impossibly well-lit office."** Named verbatim in [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide). For a church specifically, the direct analogue is named by [Nucleus's own church-design guide](https://www.nucleus.church/blog/church-website-design) (fetched in full): stock photos of unfamiliar people "creates the wrong expectation" because visitors compare the photo to the room they actually walk into.
23. **Abstract 3D blobs or gradient meshes floating in negative space**, used as a placeholder for having nothing else to show. 925 Studios: "abstract 3D blobs floating in space," described elsewhere as having a "plastic quality" once AI image generation is the source.
24. **Every photo boxed in a rounded-corner rectangle, uniformly, regardless of subject.** This is the visual expression of tell #10 (uniform radius) applied to imagery: the frame becomes more consistent than the content.
25. **Icon-in-a-circle as the default way to represent any abstract concept** (a colored circle behind a line icon, repeated for every feature). This is the imagery equivalent of tell #13 and is functionally interchangeable across any industry, which is the whole problem: nothing in the icon or its container is specific to the business behind it.

### Copy

26. **Vague, aspirational headline copy: "Build the future of work," "Your all-in-one platform," "Scale without limits."** Quoted directly as characteristic AI copy in [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide): "Vague, aspirational headlines lacking specificity... generic superlatives and hedging language."
27. **Eyebrow labels used as decoration rather than orientation** — an uppercase word with a leading dot and a trailing rule, placed above every single heading whether or not it adds information. Solodesign.cc's memorable phrase: "the uppercase label with a dot in front and a thin line trailing after it... the 'here's the thing' of landing pages." This is directly relevant to the reported FBCM design, which uses small-caps eyebrows over every heading — see the practical note in Section 4.

### Motion

28. **A uniform fade-up-on-scroll applied to every section, every time, with the same duration and easing.** [Nielsen Norman Group's research](https://www.nngroup.com/articles/scroll-animations/) by Aurora Harley found this specifically frustrates users on task-focused sites: participants said "I don't like how everything comes together when I'm scrolling down," and NN/g's guidance is to reserve such animation for secondary content, apply it once rather than repeatedly, and skip it entirely on sites where visitors are trying to get something done (medical, financial, B2B — a church "plan a visit" or "give" page is squarely in this category).
29. **Buttons and cards that snap into their hover/active state instead of easing**, or conversely apply the exact same generic ease-in-out to everything with no relationship to what the interaction means. Named in [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide): "buttons that snap instead of easing... motion must communicate state, direct attention, or reinforce brand personality," implying that motion applied without that intent is a tell rather than a polish layer.

### Component tells

30. **Pill-shaped buttons as the only button shape on the page**, used regardless of size or context. Part of the same "one radius everywhere" family (tell #10).
31. **A colored top or left border on cards** (frequently the brand accent color) as the single device used to make an otherwise identical card feel "on brand." Developers Digest pattern #11: "colored borders on cards, usually on the top or left edge." This is a direct, named match for the FBCM description of "gold top-border cards" in the prompt: the technique is a recognized generic tell, not a bespoke solution, because it is the cheapest possible way to inject a brand color into a component library's default card with zero other changes.
32. **Small-caps or all-caps "eyebrow" labels placed above every section heading as a structural habit rather than a case-by-case decision.** Combines tells #5 and #27; flagged again here because a template that puts an eyebrow over literally every heading (rather than the few that need one) is treating the device as furniture, which is the generic behavior.

## 2. Why it happens

**Design systems and component libraries default to the same tokens.** Tailwind and shadcn/ui ship sane, safe defaults (spacing scale, radius scale, a neutral palette) so that a team can move fast without making a hundred typographic and layout decisions up front. [Jean Galea's essay on the "Tailwind, shadcn/ui, and the New Design-System Meta"](https://jeangalea.com/tailwind-shadcn-design-system-meta/) frames this directly: shadcn's code-you-own model means nothing stops a team from customizing it, but "many products settle for a 'good enough' design that mimics the default shadcn look, forfeiting a chance at a truly unique user experience" — the tool isn't at fault, the unmodified defaults are. The same point is made about older component systems (Bootstrap, Material UI) in the same piece: any pre-built system, AI-assisted or not, produces sameness the moment its tokens go untouched.

**The model's training distribution rewards the median, not the outlier.** An LLM predicts the statistically most likely continuation of a design prompt. [Shuffle's analysis](https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/) states this plainly: "AI doesn't 'design' websites, it predicts patterns... the model defaults to the most statistically common layout it has seen." Because the training data itself is full of Tailwind/shadcn/Bootstrap sites, the model's "default" is a compounding of everyone else's defaults; a feedback loop then makes it worse, per the same source's observation that one viral purple-gradient site becomes training data that makes every subsequent AI tool reach for purple gradients "the next week."

**Underspecified prompts abdicate the decisions that create distinctiveness.** Multiple sources converge on this: [dev.to's "why AI websites all look the same"](https://dev.to/gdg/why-ai-websites-all-look-the-same-and-how-to-build-something-different-1gan) and [Superdesign's "5 fixes"](https://superdesign.dev/blog/how-to-make-ai-ui-look-less-generic) both argue the failure starts before generation: a prompt that says "modern," "clean," or "professional" gives the model nothing to differentiate on, so it falls back to the median. Superdesign's diagnosis is sharper still: the problem isn't the model, it's the workflow — "when one prompt handles taste, exploration, and implementation simultaneously, it defaults to safe, average outputs," because no single pass has room to separate a creative decision from an implementation shortcut.

**No art-direction step exists in most AI-assisted or template-based workflows.** A magazine layout goes through a designer who chooses, per spread, where to break the grid; a component-library site goes straight from wireframe to shipped page with no equivalent pass. [Andy Clarke's Smashing Magazine piece](https://www.smashingmagazine.com/2018/04/art-directing-web-css-grid/) exists specifically to reintroduce that missing step into web work via CSS Grid template areas — implying its absence, not any technical limitation, is the default state of most web builds.

**No photography or illustration budget means stock or generated imagery fills the gap.** This is less a stated argument in any one source and more the throughline connecting tells #22-25: a distinctive photo of the actual space, people, or product costs a shoot; a rounded-corner stock photo or an AI-generated blob costs nothing, so it becomes the default whenever the budget line for original imagery is zero. [Nucleus's church-specific guidance](https://www.nucleus.church/blog/church-website-design) makes the cost of skipping this explicit for churches: a stock photo "creates the wrong expectation" for a first-time visitor, which is a conversion problem, not just an aesthetic one.

**Safe pairings get reused because they are legible as "acceptable" rather than because they are right for the brand.** The Space Grotesk/Instrument Serif/Geist trio (tell #2) and the amber "tasteful startup" accent (tell #19) are both explicitly named as choices made *because* they read as safe defaults for "good design" in general, not because anyone decided they suited a specific brand. Solodesign.cc's framing — reaching for "the next safe distinctive color" once the first safe color is blocked — describes a system optimizing for not-being-wrong rather than for being right.

## 3. What distinctive sites do instead

Fifteen concrete, sourced techniques, roughly ordered from typography through motion to process.

1. **Give type real scale contrast and let the display face carry personality the body face doesn't.** [Jason Santa Maria's *On Web Typography*](https://www.printmag.com/featured/jason-santa-maria-on-web-typography/) argues typography is "a design's voice, and the most powerful tool to communicate with readers" — meaning the choice of face is a communication decision, not a neutral default. Practically: pick one typeface with real character for headings (a serif with personality, not a geometric sans doing double duty) and keep the workhorse face for body copy, rather than one face for everything.
2. **Use old-style (text) numerals and real small caps where the typeface supports them**, instead of the lining numerals and faux small-caps a browser fakes by shrinking capitals. [A List Apart's "Web Typography: Numerals"](https://alistapart.com/article/web-typography-numerals/) documents this as a discipline distinct from just picking a nice font: most professional OpenType fonts carry both numeral styles as features, and using the text-figure style in running prose is a small, specific signal of typographic care that a template never bothers to turn on.
3. **Treat one planned rule-violation per section as the mark of art direction, not an accident.** The clearest single formulation found: "the grid earns its keep by being obeyed, and then, exactly once, disobeyed. An image crosses the gutter. A headline trespasses onto a photography." ([Remember Style's "Editorial Web Design"](https://remember.style/editorial), fetched in full). This is the opposite of a template, which never breaks its own grid because it has no "once" to spend — every section looks the same because none of them earns a deviation.
4. **Use CSS Grid template areas to give each section its own layout logic instead of reusing one component shape everywhere.** [Andy Clarke's Smashing Magazine piece](https://www.smashingmagazine.com/2018/04/art-directing-web-css-grid/) (fetched in full) demonstrates positioning the same underlying content into different grid zones per section: a wide, dramatic image span for an emotional moment, a fragmented, off-grid arrangement for tension, then a calm, justified column for resolution. The point is that layout itself is doing narrative work, section by section, rather than being one repeatable card component.
5. **Build in asymmetry and eye-line tension rather than centering everything.** Clarke's piece frames whitespace as an active compositional tool ("whitespace draws the eye down to the bold paragraph") and connects deliberately unbalanced element placement to how attention moves through a page — the opposite of the centered-hero default (tell #8).
6. **Let images and type overlap and cross the container edge on purpose.** The editorial-grid technique above depends on this: a photo or headline is allowed to bleed past where a template's max-width container would clip it, which is precisely what produces the "trespass" moment Remember Style names as the difference between art direction and a template.
7. **Vary column logic instead of defaulting to twelve.** Search summary from an editorial-grid comparison notes that "twelve-column grids dominate web design for one reason: divisibility" — practical, not expressive — while "magazine spreads often run five, seven, or even nine columns, with gutters sized to the text column rather than the total page width. The asymmetry is a feature." A church site with long-form content (sermon transcripts, history pages, staff bios) has more license to borrow this than a SaaS dashboard does.
8. **Use real photography of the actual place and people as the layout, not as decoration inserted into a layout.** Nucleus's church-specific advice: replace unfamiliar stock faces with "real photos of" the actual members, worship services, and building, because a first-time visitor is comparing the photo against the room they are about to walk into. This is a stronger claim than "use better photos" — it says the photography should shape the composition (a real sanctuary interior suggests a very different hero treatment than a stock photo of hands raised at a generic sunset).
9. **Apply restraint to motion: animate once, on entry, and only on secondary content.** [NN/g's research](https://www.nngroup.com/articles/scroll-animations/) by Aurora Harley gives the specific, actionable rule: reserve scroll-triggered effects for supporting graphics rather than primary reading content, trigger them once rather than every time an element re-enters the viewport, and skip them altogether on task-focused pages (a "plan a visit," "give," or service-times page counts as task-focused). This directly reverses tell #28.
10. **Make motion communicate state or brand personality, not just exist.** [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide) frames the bar precisely: "motion must communicate state, direct attention, or reinforce brand personality" — meaning every eased transition should be answerable with "why does this move the way it does," not just "because a component library shipped a default transition."
11. **Use color as a structural/semantic system, not a decorative fill.** [925 Studios](https://www.925studios.co/blog/ai-slop-web-design-guide) recommends building "a semantic system using CSS variables with functional names (`--color-action-primary`, not `--color-gradient-start`)" — the point being that a distinctive palette is one where every color choice answers to a role in the design, so a gold accent means something specific (a call to action, a single accent moment) rather than being reused as a decorative top-border on every card (tell #31).
12. **Retire the icon-in-a-circle and the identical feature-card grid; let content density vary by section instead of forcing everything into the same box.** This is the direct antidote to tells #13 and #25: a section about staff should look and behave differently from a section about service times, because they are different kinds of content, not the same card component with different words in it.
13. **State explicit "avoid" constraints, not just "aspire to" ones, when briefing any AI-assisted design pass.** [dev.to's writeup](https://dev.to/gdg/why-ai-websites-all-look-the-same-and-how-to-build-something-different-1gan) is specific: "avoid purple-to-blue gradients, glassmorphism, rounded cards in every section, or stock photography... this forces the model away from its default patterns." A brief that only says what to aim for lets the model fall back to the median on everything it wasn't told to avoid.
14. **Give the AI (or a template) concrete visual references and real content before generation, not adjectives.** The same dev.to piece: replace "modern" or "premium" with something like "feel like a contemporary editorial magazine rather than a typical SaaS dashboard," and supply actual copy, photos, and testimonials up front, because real content shapes hierarchy in a way placeholder text cannot.
15. **Separate the creative/taste decisions from the implementation pass.** [Superdesign's "5 fixes"](https://superdesign.dev/blog/how-to-make-ai-ui-look-less-generic) frames this as the root fix: plan layout, styling, and motion in text first, then hand a builder explicit specifications, rather than asking one pass to decide taste and write code simultaneously. Extracting a design system (exact colors, type scale, spacing increments, radius) into a written reference *before* generating any page is the concrete version of this.
16. **Apply "one grammar per page" discipline across every section, so the deviations you do allow read as intentional rather than as inconsistency.** (This is FBCM's own CLAUDE.md rule 17, included here because it is the flip side of technique 3: a page that varies grid logic and breaks the container needs one consistent underlying spine — one heading system, one button family, one alignment convention — or the variation reads as sloppiness instead of art direction. The distinction between "distinctive" and "inconsistent" is that the former breaks its own rule on purpose, once, against a backdrop that is otherwise disciplined.)

## 4. A test to run on a page

A short rubric to score how generic a screenshot reads, built from the tells and techniques above. Score each 0 (fully generic) to 2 (clearly intentional and specific to this brand); 20 is a perfect score, and anything under 10 is worth a redesign pass.

1. **Typeface test.** Cover the logo and any text that names the organization. Could this face and this pairing belong to any SaaS product, and is it Inter or an Inter-equivalent doing all the work? (0 = yes to both; 2 = a display face with real character that would look wrong on a competitor's site)
2. **Copy swap test.** Replace the logo and the org's name with a competitor's. Does the headline copy still work verbatim? (0 = yes, nothing would need to change; 2 = the copy is unusable without this specific organization's facts)
3. **Grid-break test.** Find the one place per page where an image, headline, or element crosses the container edge or breaks the established grid. Is there one, deliberately? (0 = nothing ever breaks the grid, everything sits inside a centered max-width box; 2 = there is exactly one clear break and it lands on the moment that matters)
4. **Radius/padding audit.** Measure the corner radius and vertical padding on three different components (a card, a button, a section band). Are they identical because nobody decided otherwise, or different because the content calls for it? (0 = one radius and one padding value used everywhere; 2 = radius and rhythm vary with clear purpose)
5. **Photography test.** Is a single photo on the page one this exact organization could have taken, of this exact place or these exact people? (0 = generic stock or an AI-generated illustration; 2 = a specific, recognizable photo of the actual place/people)
6. **Color-role test.** Pick the brand accent color. Can you name the one or two things it is reserved for, or does it appear on every card border, badge, and icon indiscriminately? (0 = used as decoration everywhere; 2 = used sparingly, tied to a specific role like a single CTA)
7. **Eyebrow/label audit.** Count how many section headings carry an eyebrow label above them. If it's "all of them," that's a tell regardless of how the label looks. (0 = every heading has one; 2 = used only where it earns its place, or not at all)
8. **Motion test.** Scroll the page slowly. Does every section fade up identically regardless of what it contains, and does it happen every time you scroll back past it? (0 = yes to both; 2 = motion is restrained, purposeful, and single-fire)
9. **Silhouette test.** Squint at the page (or blur it) until only shapes remain. Is the silhouette recognizable as this specific page, or could it be any landing page in the same category? (0 = generic hero-block-block-block silhouette; 2 = a distinct, memorable shape)
10. **Section-density test.** Do all sections feel like they take up the same amount of visual "weight" (same band height, same card count), regardless of how important the content is? (0 = uniform weight throughout; 2 = the most important content is visibly given more room and attention than routine content)

## 5. Church sites specifically

Findings that name churches directly, not general design advice retrofitted.

- **[Nucleus's own church-design guide](https://www.nucleus.church/blog/church-website-design)** (fetched in full) is the most directly useful source found. It names three generic patterns specific to churches: (1) "generic slogans that could belong to any church," which dilute identity precisely because they're interchangeable across denominations and cities; (2) rotating image sliders carrying multiple competing messages, which the guide describes as "movement without clarity" rather than focus; (3) stock photography of unfamiliar people, which "creates the wrong expectation" because a first-time visitor is silently comparing the photo to the actual room and actual congregation they're about to walk into — a credibility cost specific to churches, where the whole point of the site is to get someone to show up in person.
- The same source's prescription is concrete rather than aesthetic: use real photos of the church's own members, worship, volunteers, and building; write a short, specific statement of "the kind of community you are" and "the place you serve" rather than a generic mission-style slogan; commit to one clear visitor-facing action ("Join a Group," "Plan a Visit") rather than several competing CTAs; and keep visual complexity low so the one clear path isn't buried.
- **Free/generic church website templates converge on a recognizable stock formula**, per a general search of the template marketplace landscape (search summary only, not independently verified against a specific named critique essay): a stock photo of raised hands at sunset, a countdown timer to the next service, and a row of three icons for "beliefs / ministries / get involved." This is functionally the same "hero + three cards" structure named in Section 1's tell #7, applied to the church vertical specifically — meaning the generic-AI-design problem and the generic-church-template problem are, structurally, the same failure with different stock photography.
- **Church Marketing Sucks**, one of the longest-running church-communications critique sites, has published a recurring line of commentary that church website design "still sucks" because of "poor navigation, horrid design, and sub-optimal content," and separately that church communicators resist starting from strategy (audience, goals, message) before jumping to visual design (search summary of [churchmarketingsucks.com](https://churchmarketingsucks.com/read-this-first/) and related posts; the site's archives were not fetched in full). The throughline relevant here: a church site's generic look is frequently a downstream symptom of skipping the strategy step, not a font or color problem in isolation — which lines up with Section 2's finding that underspecified briefs, not tool limitations, are the root mechanical cause of generic output in general.
- No essay specifically framed around "AI-generated church websites" as a distinct sub-genre was found; the church-specific commentary located treats the sameness problem as a template/stock-content problem (pre-dating the AI-tooling wave) rather than an AI-specific one. The FBCM brief connecting "generic and plain, like AI design" to a page-builder + Tailwind + component-driven site is consistent with Section 2's argument that template-driven and AI-driven genericness share the same mechanical cause: unmodified defaults, applied without an art-direction pass.
